# Meridian — Playwright Flaky Analyzer Demo

A realistic, enterprise-grade Playwright end-to-end suite for **Meridian**, a fictional B2B
analytics & delivery SaaS. It exists to showcase every capability of
[`playwright-flaky-analyzer`](https://github.com/shivani26singh/playwright-flaky-analyzer): flaky
detection, regression/fixed/newly-failed classification, root-cause investigation, evidence,
browser comparison, and trend analysis — in one polished HTML dashboard.

> The dashboard is pre-generated and committed — just open **[`flaky-report/index.html`](./flaky-report/index.html)** directly, no install or build step needed. Want to regenerate it yourself? Clone → `npm install` → `npm run report`.

## What's inside

- **~70 tests** across 11 modules (auth, dashboard, projects, tasks, reports, analytics, billing,
  notifications, users, admin, settings), run on **chromium, firefox, and webkit**.
- A **captured 20-run CI history** (`ci-runs/results-run1.json … results-run20.json`) so the dashboard
  can be produced on a fresh clone **without standing up the Meridian app**. This is exactly the data
  a real project's Playwright reporter emits across CI runs — see [How the data is produced](#how-the-report-data-is-produced).
  20 runs also gives the optional Flaky Tests Trend and Retries Per Run charts enough points for a
  visible trend, not just a two-run blip.
- A distribution that reads like a mature suite mid-sprint: **~62% healthy**, plus stable failures,
  flaky tests, newly-failed, and fixed — with **all 9 failure categories** and **all
  20 investigation rules (RC-001 … RC-020)** exercised by real tests.
- Real evidence: screenshots, videos, and Playwright traces attached to failing runs.

## Prerequisites

- Node.js **>= 18**
- npm

## Install

This demo lives at `demo-project/` inside the [`playwright-flaky-analyzer`](https://github.com/shivani26singh/playwright-flaky-analyzer) repo.

```bash
git clone https://github.com/shivani26singh/playwright-flaky-analyzer.git
cd playwright-flaky-analyzer/demo-project
npm install
```

Playwright is only needed if you want to run the **live** suite against a real Meridian environment
(see below). For the demo dashboard you do **not** need the browsers.

```bash
# only for the live suite:
npx playwright install --with-deps
```

## Generate the dashboard (the demo)

```bash
npm run report
```

This runs three steps:

1. `report:evidence` — writes small screenshot/video/trace assets to `evidence/`.
2. `report:data` — regenerates the 20-run CI history in `ci-runs/` from `data/catalog.js`.
3. `report:html` — runs the analyzer over `ci-runs/` and writes the **`flaky-report/`** bundle (`index.html` + `assets/` with copied screenshots/videos/traces).

Open `flaky-report/index.html` in any browser — it's a self-contained, portable bundle (zip the folder and it still works anywhere, no dependency on the original Playwright output). Use
[`docs/DEMO_GUIDE.md`](docs/DEMO_GUIDE.md) as your walkthrough script.

> This demo lives inside the analyzer repo, so the `report:html` step also works via the local CLI without installing the published package:
> `node ../src/cli/run-analysis.js analyze`

## Expected output

The dashboard summarizes **20 nightly runs** of ~231 test executions each (70 tests × 3 browsers):

| Section | What you'll see |
|---|---|
| **Suite Summary** | ~62% health score; Stable Pass / Stable Fail / Flaky / Newly Failed / Fixed counts |
| **Retry Timeline** | Per-run pass/fail and retry bars across all 20 runs, with a trend line |
| **Browser Statistics** | chromium vs firefox vs webkit fail/flaky rates (webkit-only and firefox-only failures included) |
| **Investigation** | One card per failing/flaky test with a root cause, confidence, and 5 suggested fixes — **all 20 RC rules** appear |
| **Failure Categories** | All 9: timeout, locator, assertion, network, backend, authentication, environment, data, unknown |
| **Failure Frequency** | Tests ranked by how often they fail (the broken subscription card tops it) |
| **Slowest Tests** | PDF export and query-editor tests lead |
| **Evidence** | Screenshot thumbnails (click to preview), plus Trace and Video links on failing tests |

## Flaky Tests Trend, Retries Per Run & CI Gate

The analyzer always renders both **Flaky Tests Trend** and **Retries Per Run** charts (bar+line, with a plain-language interpretation) in the dashboard generated by `npm run report` above — no flag needed. Both are built from the same 20 runs already loaded by this demo's `flaky.config.json` (`lookbackRuns: 20`), aligned on the same Run 1...20 axis so you can compare a flaky-count spike against a retry-count spike directly.

The CI quality gate is a separate, opt-in flag:

```bash
npm run report:gate
```

This is the same `report:html` step, plus `--max-flaky 5` (fails the command with a non-zero exit code if the flaky-test count exceeds 5 — the report is written first either way). This demo's committed 20-run history has 28 flaky tests (the dataset is deliberately messy so every rule/category gets exercised), so running this script is expected to **exit non-zero**; that's the CI-gate behavior working as intended, not a bug. A worked CI example (Playwright → analyzer → flaky-count threshold → published HTML artifact) is in [`docs/azure-pipelines.example.yml`](../docs/azure-pipelines.example.yml) of the analyzer repo.

## Run the live suite (optional)

The `tests/` specs are the real suite the CI history models. To run them against a live
environment:

```bash
export MERIDIAN_BASE_URL="https://staging.meridian.io"   # your environment
npm test                    # writes ci-runs/results-run<N>.json via the custom reporter
# run it several times (nightly / per-commit) to build history, then:
npm run report:html
```

The custom reporter is configured in `playwright.config.js`:

```js
reporter: [
  ["list"],
  ["playwright-flaky-analyzer/reporter", { outputFile: "./ci-runs/results.json" }],
]
```

Each run writes `results-run<N>.json`; the analyzer compares the last N runs.

## How the report data is produced

The analyzer never runs your app — it compares the JSON its Playwright reporter emits across CI
runs. To make this demo self-contained, `data/catalog.js` describes the suite (each test's
classification, realistic failure, evidence, retries and per-browser behavior) and
`generate-ci-history.js` renders it into twenty runs of that exact reporter format. It's a curated
snapshot of a real-looking CI history, not random noise — `npm run verify` proves every rule and
category is covered by a real, plausible failure. Point the analyzer at your own
`results-run*.json` and you get the same dashboard for your suite.
